# Decisions

Settled product decisions. Add new ones at the bottom with the date. To change a decision, add a new entry that replaces it rather than editing the old one.

| # | Date | Decision |
| --- | --- | --- |
| 1 | 2026-09-24 | Occurrences are combined into one Project Part **by part number**, even across Onshape documents. |
| 2 | 2026-09-24 | Onshape BOM changes are **shown to the user and applied only after approval**, never automatically. |
| 3 | 2026-09-24 | **Subassembly quantities multiply** (Swerve Module ×4 with 2 bearings = 8 bearings). |
| 4 | 2026-09-24 | Part type (COTS / Custom) is **set manually**, not read from Onshape. |
| 5 | 2026-09-24 | One vendor order **may combine items from several projects**; each line item belongs to one project. |
| 6 | 2026-09-24 | Accepted items go to a **team-wide Order List**, grouped by vendor, filterable by project. |
| 7 | 2026-09-24 | Multi-project invoices **split automatically**: each project pays its own lines; shipping and tax split in proportion to line cost. |
| 8 | 2026-09-24 | Archived projects are read-only **except** receiving deliveries and adding invoices for open orders. |
| 9 | 2026-09-24 | All quantities are **whole numbers**. |
| 10 | 2026-09-24 | A custom part may **switch between in-house and outsourced**; Completed + Received both count toward Ready. |
| 11 | 2026-09-24 | BeanPARTS connects to Onshape through **one team account**; users don't need Onshape logins. |
| 12 | 2026-09-24 | **Offline mode is not in V1.** |
| 13 | 2026-09-24 | **No spreadsheet import in V1**; projects start fresh. |
| 14 | 2026-09-24 | **No notifications in V1.** |
| 15 | 2026-09-24 | "Received" is the standard term (not "Delivered"). |
